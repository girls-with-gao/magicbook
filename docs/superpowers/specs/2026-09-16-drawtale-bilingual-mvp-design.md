# 그림이야기 이중언어 MVP 설계서

- 작성일: 2026-09-16
- 대상 대회: Wanted AI Championship 2026
- 서비스명: 그림이야기 (DrawTale)
- 상태: 사용자와 핵심 방향 합의 완료

## 1. 한 줄 정의

> 그림이야기는 아이의 그림일기를 AI가 한국어와 영어의 짧은 이야기로 확장하고, 마지막 질문을 통해 아이가 다시 종이 위에 다음 상상을 그리게 하는 이중언어 창작 서비스다.

## 2. 해결할 문제

외출 중 대기하는 시간에 부모가 아이에게 화면을 보여주어야 하는 상황은 피하기 어렵다. 이때 아이가 속도가 빠르고 끊임없이 추천되는 영상을 수동적으로 반복 시청하기 쉽다.

그림이야기는 화면 사용을 없애려고 하지 않는다. 대신 이미 존재하는 화면 시간을 아이의 그림과 언어를 활용하는 3분 내외의 창작 경험으로 바꾼다.

## 3. 핵심 제품 철학

1. AI가 아이의 상상을 대신하지 않는다.
2. 아이의 원본 그림을 새로운 AI 화풍으로 덮어쓰지 않는다.
3. 이야기는 짧게 끝나야 하며 무한 스크롤·자동재생·자동추천을 제공하지 않는다.
4. 화면의 마지막 행동은 또 다른 콘텐츠를 보는 것이 아니라 종이에 그리는 것이다.
5. 한국어와 영어 중 어느 쪽이든, 아이가 이미 아는 자신의 이야기를 학습 언어로 다시 만나게 한다.

## 4. 핵심 사용자

### 1차 사용자

- 5~9세 아이를 둔 부모
- 아이의 그림일기를 보관하고 창작 놀이로 연결하고 싶은 가정
- 짧은 화면 시간을 보다 능동적인 활동으로 바꾸고 싶은 부모

### 확장 사용자

- 한국어가 편하고 영어를 배우는 아이
- 영어가 편하고 한국어를 배우는 아이
- 두 언어를 함께 사용하는 다문화·재외동포 가정

## 5. MVP 사용 흐름

### 1단계: 그림일기 올리기

부모가 아이의 그림일기 사진을 올린다. 아이의 이름은 실명 대신 별명만 받고, 연령은 문장 난이도를 정하는 데만 사용한다.

### 2단계: AI가 읽은 내용 확인

AI가 그림의 등장인물·장소·사물·분위기와 손글씨를 분석한다. 부모에게 분석 결과를 보여주고, 손글씨를 잘못 읽은 부분만 고칠 수 있게 한다. 확인 전에는 이야기를 생성하지 않는다.

### 3단계: 언어 방식 선택

다음 세 가지 보기 방식 중 하나를 고른다.

- 한국어로 읽기
- Read in English
- 한국어 + English 함께 보기

이야기 내용은 같고, 표시 언어만 달라진다. 영어를 학습하는 아이와 한국어를 학습하는 아이 모두를 지원한다.

### 4단계: 4페이지 이야기

- 원본 그림을 그대로 사용한다.
- 페이지마다 원본 그림의 다른 부분을 확대·이동해 보여준다.
- 한 페이지에 짧은 문장 1~2개를 보여준다.
- 이중언어 모드에서는 같은 의미의 한국어·영어 문장을 함께 보여준다.
- 페이지마다 학습 언어의 핵심 단어는 최대 2개로 제한한다.
- 이야기 전체는 3분 안에 볼 수 있는 길이로 제한한다.

### 5단계: 화면 밖으로 돌아가기

마지막 페이지에서 이야기를 부드럽게 멈추고 “다음에는 무슨 일이 생길까?”와 같은 열린 질문을 보여준다. 기본 행동 버튼은 “다음 장면을 종이에 그려보기”와 “오늘은 여기까지”다. 즉시 재생성 버튼은 두지 않는다.

## 6. 경쟁 서비스와의 차이

해외에는 StoryBloom, Doodle Stories, Drawtopia, PeppyTiger, ArtifyTales 등 아이의 그림을 AI 동화로 바꾸는 서비스가 이미 있다. 그러므로 “그림이 동화가 된다”는 단독 차별점으로 사용하지 않는다.

그림이야기의 차별점은 다음 조합이다.

1. 그림만이 아니라 아이의 손글씨 그림일기를 핵심 입력으로 사용한다.
2. 새 그림을 생성하기보다 아이의 원본 그림을 보존한다.
3. 한국어↔영어 양방향 학습을 지원한다.
4. AI가 완결된 결과를 계속 제공하지 않고, 열린 결말로 다시 아이에게 창작을 넘긴다.
5. 서비스 안 재방문이 아니라 화면 이탈과 종이 활동을 성공 지표로 본다.

## 7. 현재 저장소의 구현 상태

현재 `main` 브랜치에는 작동하는 초기 프로토타입이 있다.

- Node.js 기반의 간단한 서버
- HTML, CSS, JavaScript 기반의 한 페이지 화면
- 그림·그림일기 업로드
- 별명, 나이, 일기 글, 테마, 완성형·이어쓰기형 입력
- OpenAI 이미지 분석과 이야기 생성
- API 키가 없을 때 사용하는 발표용 데모 이야기
- 4~6페이지 한국어·영어 이야기
- 영어 보기 전환
- 영어 단어와 다음 상상 질문
- 브라우저 인쇄를 이용한 PDF 저장

현재 구현과 확정 설계 사이에는 차이가 있다.

- AI가 읽은 그림·손글씨를 부모가 확인·수정하는 중간 단계가 없다.
- 한국어, 영어, 이중언어 세 가지 보기 모드가 아니라 영어 표시 버튼만 있다.
- 원본 그림을 페이지별로 확대·이동하는 이야기 화면이 아직 없다.
- 마지막 페이지에서 종이 활동으로 끝내는 전용 종료 화면이 아직 없다.
- 음성 낭독은 아직 구현되지 않았다.

## 8. 구현 구조 결정

대회 제출용 첫 공개 버전은 Next.js App Router 기반의 모바일 우선 웹앱으로 이전한다. 현재 Node.js 프로토타입은 이전할 때 동작 참고용으로 보존한다.

이유는 다음과 같다.

- 입력, AI 확인, 언어 선택, 이야기, 종료 화면이 서로 분리된다.
- AI API 키를 서버 안의 환경변수에 안전하게 두기 쉽다.
- Vercel에 바로 배포할 수 있다.
- 추후 저장, 음성, 부모 영역을 붙이기 쉽다.

### 화면 구성

1. `upload`: 그림일기 업로드와 별명·나이 입력
2. `review`: AI가 추출한 등장인물·장소·사물·분위기·손글씨 확인
3. `language`: 한국어·영어·이중언어 표시 방식 선택
4. `story`: 4페이지 이야기
5. `offline`: 다음 그림을 유도하는 종료 화면

### AI 처리 단계

1. 이미지 용량과 형식을 검사한다.
2. 이미지에서 그림 요소와 손글씨를 구조화된 데이터로 추출한다.
3. 부모가 추출 결과를 확인·수정한다.
4. 확인된 내용으로 한국어·영어 페이지를 함께 생성한다.
5. 각 페이지에 원본 이미지에서 보여줄 영역을 지정한다.
6. 마지막 페이지에 열린 질문과 오프라인 활동 제안을 생성한다.

## 9. 데이터와 개인정보 원칙

대회 MVP에서는 회원가입과 영구 저장을 구현하지 않는다.

- 아이의 실명 대신 별명만 받는다.
- 사진을 서버의 영구 저장소에 보관하지 않는다.
- 웹 페이지에서 나가면 이야기 상태도 유지하지 않는다.
- API 키는 서버 환경변수에만 두고 브라우저 코드에 포함하지 않는다.
- 업로드 화면에 AI 처리 및 임시 사용을 알리는 안내를 표시한다.
- 업로드 자료에 아이의 얼굴, 연락처, 학교명, 주소가 보이지 않도록 부모에게 안내한다.

영구 저장이나 공유 기능을 추가할 때는 개인정보 처리방침, 부모 동의, 삭제 기능, 비공개 파일 저장소와 만료되는 임시 링크를 함께 구현해야 한다. 이 절은 법률 자문이 아니며, 실제 공개 서비스 전환 전에 공식 기준이나 전문가 검토가 필요하다.

## 10. 오류 처리

- 이미지가 없거나 지원하지 않는 형식이면 무엇을 다시 올려야 하는지 알려준다.
- 손글씨를 읽지 못해도 그림 분석 결과는 보여주고 부모가 직접 한 문장을 적을 수 있게 한다.
- AI 응답이 지연되면 단계별 대기 문구를 보여준다.
- API 호출이 실패하면 입력내용을 유지하고 다시 시도하게 한다.
- API 키가 없는 경우에는 발표용 예제 그림과 예제 이야기를 이용하는 데모 모드를 제공한다.
- 부적절한 내용이 감지되면 자극적인 결과를 표시하지 않고, 부모에게 다른 그림을 사용해 달라고 안내한다.

## 11. 검증 기준

### 기능 확인

- 예제 그림일기로 전체 5단계를 끝까지 진행할 수 있다.
- AI가 읽은 손글씨를 부모가 수정하면 최종 이야기에 반영된다.
- 한국어, 영어, 이중언어 보기가 모두 같은 이야기를 유지한다.
- 연령이 달라지면 문장 길이와 어휘 난이도가 달라진다.
- 이야기는 항상 4페이지로 완료되고 마지막에 열린 질문이 나온다.
- API 키가 없어도 데모 모드가 작동한다.

### 화면 확인

- 휴대폰에서 편안하게 사용할 수 있다.
- 주요 버튼은 어린이가 누르기 쉽게 크고 항상 같은 위치에 있다.
- 한 화면에서 요구하는 주요 행동은 하나다.
- 한 페이지의 이야기 글은 휴대폰에서 스크롤 없이 읽을 수 있다.
- 생성 중, 실패, 완료 상태가 글과 화면 변화로 명확하게 구분된다.

### 안전 확인

- API 키는 브라우저에서 확인할 수 없다.
- 서버는 허용하는 이미지 형식과 용량을 다시 검사한다.
- 웹앱은 이미지·이야기를 영구 저장하지 않는다.
- 예제 속의 실명·연락처·학교명·주소가 결과 화면에 노출되지 않는다.

## 12. 대회 시연 시나리오

1. 예제 그림일기를 올린다.
2. AI가 읽은 “바닷가, 조개, 엄마와 아이, 신나는 기분”과 손글씨를 보여준다.
3. 잘못 읽은 단어 하나를 고친다.
4. 이중언어 모드를 고른다.
5. 원본 그림을 활용한 4페이지 이야기를 넘겨본다.
6. 한국어·영어 문장과 핵심 단어를 보여준다.
7. 마지막 질문이 어떻게 다시 종이 그림으로 이어지는지 설명한다.

## 13. 범위에서 제외한 기능

다음 기능은 가능성은 있지만 대회 MVP에서는 제외한다.

- 회원가입과 로그인
- 아이별 성장 아카이브
- 영구 이미지 저장
- 실물 동화책 제작·배송
- 만화·애니메이션·영상 자동 생성
- 점수, 연속 학습, 일일 미션
- 추천 피드와 무한 스크롤
- 한국어·영어 외 추가 언어

## 14. 성공 기준

아이가 앱에 오래 머무르는 것은 성공이 아니다. 그림일기를 올린 뒤 3분 안에 이야기를 다 보고, 아이가 “나도 다음 장면을 그릴래”라고 말하며 화면을 떠나는 것이 MVP의 성공이다.
