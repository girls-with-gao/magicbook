# 그림이야기 첫 화면 통합 및 두 번 선택 이야기 설계

- 작성일: 2026-09-17
- 상태: 사용자 방향 승인 후 구현 전 검토
- 목표 시간: 한 이야기당 약 3~4분

## 1. 목표

팀원 버전 첫 화면의 풍성한 인상과 현재 Next.js 버전의 단계별 사용 흐름을 합친다. 4쪽 이야기 분량은 유지하되, 이야기 사이에 독립된 선택 화면을 두 번 넣어 아이가 이야기를 움직였다는 느낌을 강화한다.

핵심 원칙은 다음과 같다.

1. 첫 화면만 보아도 그림이 동화가 되는 결과를 예상할 수 있어야 한다.
2. 업로드 후에는 한 화면에서 한 가지 행동만 하도록 단계별로 안내한다.
3. 아이의 두 선택이 이후 장면과 결말에 실제로 반영되어야 한다.
4. 전체 사용 시간은 3~4분으로 끝내고 마지막에는 종이 활동으로 돌아간다.
5. 즉시 재생성, 무한 추천, 반복 보상은 추가하지 않는다.

## 2. 확정한 경험 흐름

전체 순서는 다음과 같다.

1. 첫 화면과 그림 업로드: 약 40초
2. AI 분석 결과를 부모가 확인·수정: 약 30초
3. 한국어·영어·함께 보기 중 선택: 약 10초
4. 이야기 1쪽: 약 20초
5. 첫 번째 선택 화면: 약 20초
6. 선택이 반영된 이야기 2~3쪽: 약 50초
7. 두 번째 선택 화면: 약 20초
8. 두 선택이 반영된 이야기 4쪽: 약 25초
9. 다음 장면을 종이에 그리도록 제안: 약 15초

상단의 큰 진행 단계는 현재와 같은 다섯 단계로 유지한다.

- 그림 올리기
- 부모 확인
- 언어 고르기
- 이야기 보기
- 다시 그리기

두 선택 화면은 `이야기 보기` 단계 안에 포함한다. 따라서 화면 수가 늘어나도 전체 구조가 복잡해 보이지 않는다.

## 3. 첫 화면 통합 디자인

첫 화면은 팀원 버전의 히어로 구성을 가져온다.

- 왼쪽 또는 위: “아이 그림이 동화가 되는 순간”이라는 핵심 문구와 짧은 설명
- 오른쪽 또는 아래: 아이의 원본 그림이 들어간 그림책 결과 미리보기
- 주요 버튼: `그림 올리고 시작하기`
- 입력 항목: 그림, 아이 별명, 나이, 개인정보 확인
- 보조 버튼: `사진이 없나요? 예제로 시작하기`

팀원 버전의 모든 입력 항목을 한꺼번에 가져오지는 않는다. 테마, 주인공 이름, 특징 등은 첫 화면을 길게 만들기 때문에 MVP에서는 AI 분석과 부모 확인 단계에서 다룬다.

모바일에서는 핵심 문구 → 그림책 미리보기 → 업로드 영역 → 최소 입력 순서로 한 줄 배치한다. 버튼은 아이와 부모가 누르기 쉽도록 최소 높이 48px을 유지한다.

## 4. 독립 선택 화면

선택 화면은 이야기 페이지와 분리한다. 화면에는 다음 정보만 보여준다.

- 현재 장면을 보여주는 원본 그림 영역
- “수민이가 결정할 차례!”와 같은 짧은 안내
- 질문 한 문장
- 그림 문자와 문구가 포함된 큰 선택 버튼 두 개
- 현재 선택이 다음 이야기와 결말에 반영된다는 안내

첫 번째 선택은 탐험 방향을 결정한다.

- 예: `바닷속 길로 간다` / `구름 위 길로 간다`

두 번째 선택은 문제 해결 방식을 결정한다.

- 예: `친구에게 도움을 청한다` / `용기를 내어 직접 해본다`

선택지는 정답·오답으로 나누지 않는다. 무섭거나 벌을 받는 결말, 아이를 탓하는 문장은 생성하지 않는다.

## 5. 이야기 분기 구조

AI는 첫 생성 시 필요한 분기를 함께 만든다. 아이가 선택한 뒤 추가 AI 요청을 보내지 않는다. 이렇게 하면 선택 직후 기다리는 화면 없이 다음 장면이 바로 열린다.

구조는 다음과 같다.

```text
공통 1쪽
├─ 첫 선택 A
│  ├─ A 전용 2~3쪽
│  ├─ 두 번째 선택 A1 → A1 결말 4쪽
│  └─ 두 번째 선택 A2 → A2 결말 4쪽
└─ 첫 선택 B
   ├─ B 전용 2~3쪽
   ├─ 두 번째 선택 B1 → B1 결말 4쪽
   └─ 두 번째 선택 B2 → B2 결말 4쪽
```

사용자가 실제로 읽는 분량은 항상 네 쪽이다. 생성 데이터에는 공통 1쪽, 두 갈래의 중간 장면, 네 갈래의 결말이 포함된다.

각 선택지와 모든 이야기 문장은 한국어와 영어를 함께 가진다. 표시 방식만 사용자가 고른 언어 모드에 따라 달라진다.

## 6. 화면 구성 단위

현재 `StoryStudio`의 큰 다섯 단계를 유지하면서 이야기 단계 내부를 작은 단위로 나눈다.

- `StoryPage`: 원본 그림, 문장, 단어, 듣기, 앞·뒤 이동
- `ChoicePage`: 질문과 두 개의 선택 버튼
- `StoryProgress`: 현재 이야기 1~4쪽과 선택 위치 표시
- `OfflineEnding`: 선택 결과를 한 줄로 되짚고 종이 그리기 제안

선택 기록은 현재 실행 중인 브라우저 상태에만 둔다. 사진, 이야기, 선택 기록을 서버나 데이터베이스에 저장하지 않는다.

## 7. 데이터 흐름

1. 부모가 그림과 기본 정보를 입력한다.
2. `/api/analyze`가 그림과 손글씨를 분석한다.
3. 부모가 분석 내용을 수정하고 확정한다.
4. `/api/story`가 두 단계 분기를 포함한 전체 이야기를 한 번에 생성한다.
5. 브라우저는 첫 번째·두 번째 선택을 기억하고 해당 분기의 장면을 즉시 보여준다.
6. 마지막 화면은 두 선택을 반영한 열린 질문을 제시한다.

OpenAI 키가 없을 때는 같은 분기 구조를 가진 발표용 예제 이야기를 사용한다.

## 8. 오류 처리

- 이미지 형식과 용량 검사는 현재 규칙을 유지한다.
- AI 분석이 실패하면 입력값을 지우지 않고 다시 시도 버튼을 보여준다.
- AI가 분기 일부를 빠뜨리거나 형식을 잘못 만들면 안전한 발표용 분기 이야기로 대체한다.
- 이야기 생성 중에는 버튼을 잠가 중복 요청을 막는다.
- 선택 버튼은 한 번 누르면 다음 화면으로 이동한다. 뒤로 가도 선택 기록은 유지한다.
- 새로고침하면 개인정보 보호 원칙에 따라 업로드 사진과 이야기는 초기화한다.

## 9. 확인 방법

자동검사에서 다음을 확인한다.

- 첫 번째 선택은 정확히 두 개다.
- 각 첫 번째 선택 아래의 두 번째 선택도 정확히 두 개다.
- 모든 경로에서 아이가 읽는 이야기는 정확히 네 쪽이다.
- 네 가지 결말 경로가 모두 존재한다.
- 한국어·영어·함께 보기에서 같은 선택 경로가 유지된다.
- AI 키가 없어도 예제 분기를 끝까지 진행할 수 있다.
- 잘못된 AI 응답은 안전한 예제로 대체된다.

화면 확인에서는 휴대폰 크기로 모든 경로를 한 번씩 눌러보고, 버튼이 겹치거나 가로로 넘치지 않는지 확인한다.

## 10. 이번 작업 범위에서 제외

- 이야기 분기를 데이터베이스에 저장하기
- 선택 결과에 점수나 정답 표시하기
- 세 번째 이상의 선택 추가
- 선택을 반복해 모든 결말을 수집하는 기능
- 즉시 다시 만들기와 무한 이야기 추천
- 회원가입, 공유, 성장 기록

이 기능들은 짧고 건강한 스크린타임이라는 방향과 대회용 MVP 범위를 지키기 위해 제외한다.
